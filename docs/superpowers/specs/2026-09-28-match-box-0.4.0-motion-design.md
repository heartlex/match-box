# match-box 0.4.0: motion helpers for applications

Date: 2026-09-28
Status: approved for planning
Builds on: `docs/superpowers/specs/2026-09-28-match-box-v2-step1-followups-design.md`

## 1. Purpose and scope

`0.3.0` gave the components their own motion. This release gives
applications four helpers for motion between and around elements, in a
new public subpath, `match-box/motion`:

| Helper | Does |
|---|---|
| `reveal` | Animates elements the first time they enter the viewport |
| `stagger` | Plays one animation on a group of elements, offset in time |
| `flip` | Animates elements from their old layout to the new one after a DOM change |
| `exit` | Animates an element out, then removes it |

The API is for anyone using match-box, with the same docs, tests, and
stability as the components. It ships as `0.4.0`. The roadmap:

| Release | Content |
|---|---|
| `0.4.0` (this spec) | `match-box/motion` |
| `0.5.0` | Step 2 form controls: text field, checkbox, switch |
| Later | Step 3 select, step 4 combobox |

Success means:

- each helper works on Chromium, Firefox, and WebKit, in light and shadow
  DOM;
- every duration and easing can come from the motion tokens, and a theme
  that zeroes the durations turns every helper off;
- under `prefers-reduced-motion: reduce` no helper calls `animate()`, and
  each applies its end state at once;
- no helper leaves content hidden or focusable while invisible, and
  `exit` leaves no element in the DOM unless given `remove: false`.

### Non-goals

- A timeline or sequence object. Sequencing is `await` and `Promise.all`.
- Exported keyframe presets. Defaults are built in; custom effects pass
  `keyframes`.
- A reveal that replays when a target re-enters the viewport.
- CSS scroll-driven animations.
- A wrapper over the View Transitions API.
- Lit directives or declarative elements. Framework adapters can wrap the
  functions later.
- Changes to the components. They keep their `0.3.0` motion, and
  `mb-listbox` does not import `match-box/motion`.

## 2. Package

- Source in `src/motion/`; `package.json` exports `./motion` like the
  other subpaths. It depends on the DOM only: nothing from `lit`,
  `match-box/core`, or `match-box/components`.
- Exports: `reveal`, `stagger`, `flip`, `exit`, and their option types
  `RevealOptions`, `StaggerOptions`, `FlipOptions`, `ExitOptions`, and the
  shared `MotionTiming`.
- `targets` parameters accept an `Element` or any `Iterable<Element>`
  (an array, a `NodeList`, an `HTMLCollection`). Helpers copy it into an
  array when called.

## 3. Shared rules

### Timing

Every helper takes `MotionTiming`:

| Option | Type | Meaning |
|---|---|---|
| `duration` | `'fast' \| 'medium' \| 'slow' \| number` | A token name, or milliseconds |
| `easing` | `'standard' \| 'enter' \| 'exit' \| 'spring' \| string` | A token name, or any CSS easing |
| `delay` | `number` | Milliseconds before the first animation starts; default `0` |
| `signal` | `AbortSignal` | Cancels the helper, see below |

- A token name resolves from the computed style of the target element, as
  `--mb-motion-duration-<name>` or `--mb-motion-easing-<name>`. A themed
  subtree or an override to `0ms` takes effect for the elements inside it.
- When the custom property is empty (no `tokens.css`), built-in defaults
  with the `tokens.css` values apply: `120`, `200`, `300` ms and the four
  curves.
- An easing that `CSS.supports('animation-timing-function', easing)`
  rejects falls back to `ease-out`, as in `mb-listbox`.
- `ms` and `s` durations are parsed; anything else is `0`.

### Reduced motion and zero durations

A helper animates nothing when `prefers-reduced-motion: reduce` matches or
the resolved duration is `0`. It never calls `animate()` and applies its
end state at once:

| Helper | End state |
|---|---|
| `reveal` | Targets show their own styles |
| `stagger` | Targets show their own styles |
| `flip` | `change` runs; nothing animates |
| `exit` | The target is removed (or kept, with `remove: false`) |

Returned promises resolve right after the end state applies. The
`matchMedia` check covers pages without `tokens.css`; with it, the tokens
are already `0ms`.

### Results and cancellation

- `stagger`, `flip`, and `exit` return `Promise<void>`, resolved when their
  animations finish. `reveal` returns `stop(): void`.
- Aborting `signal` cancels running animations, applies the end state, and
  resolves the promise. It never rejects, so `await exit(el)` always leaves
  `el` removed. An already aborted signal applies the end state at once.
- Promises reject only on programmer errors, such as a `change` callback
  that throws; that error is passed through after the end state applies.

## 4. `reveal`

```ts
reveal(targets: Element | Iterable<Element>, options?: RevealOptions): () => void
```

| Option | Default |
|---|---|
| `keyframes` | `[{ opacity: 0, transform: 'translateY(0.5rem)' }, { opacity: 1, transform: 'none' }]` |
| `duration` | `'medium'` |
| `easing` | `'enter'` |
| `interval` | `40` (ms between targets entering in the same callback) |
| `threshold` | `0.1` |
| `rootMargin` | `'0px'` |

- For each target, `reveal` creates the animation at once, paused at time
  `0` with `fill: 'backwards'`, so the target shows the first keyframe. It
  writes no inline styles. When the animation finishes, the target shows
  its own styles.
- An `IntersectionObserver` with `threshold` and `rootMargin` plays each
  target's animation on its first intersection and unobserves it. Targets
  in the same callback get a delay of `delay + index × interval`, in
  document order.
- A target whose bottom is above the viewport when `reveal` is called is
  shown at once, without animating (a restored scroll position).
- A `focusin` inside a target that has not played reveals it at once
  (finishes its animation), so hidden content never holds focus.
- `stop()` disconnects the observer, removes the `focusin` listeners, and
  cancels every animation that has not played, so those targets show their
  own styles. Aborting `signal` does the same.
- Calling `reveal` again on a target that is still waiting replaces the
  earlier animation for that target.

## 5. `stagger`

```ts
stagger(
  targets: Element | Iterable<Element>,
  keyframes: Keyframe[] | PropertyIndexedKeyframes,
  options?: StaggerOptions,
): Promise<void>
```

| Option | Default |
|---|---|
| `duration` | `'medium'` |
| `easing` | `'standard'` |
| `interval` | `40` |

- Target `i` animates with delay `delay + i × interval` and
  `fill: 'backwards'`, so later targets hold their first keyframe until
  they start.
- The promise resolves when every animation has finished.
- Sequencing composes with promises:

```js
await stagger(cards, [{ opacity: 0 }, { opacity: 1 }]);
await Promise.all([flip(list.children, reorder), exit(banner)]);
```

## 6. `flip`

```ts
flip(
  targets: Element | Iterable<Element>,
  change: () => void | Promise<void>,
  options?: FlipOptions,
): Promise<void>
```

| Option | Default |
|---|---|
| `duration` | `'medium'` |
| `easing` | `'standard'` |
| `scale` | `true` |

1. Read `getBoundingClientRect()` for each target.
2. Run `change` and await it.
3. Read the rects again for targets that are still connected.
4. For each target whose position or size changed, animate
   `translate(dx, dy) scale(sx, sy)` to `none`. Both keyframes carry
   `transform-origin: 0 0`, so the origin applies only while the animation
   runs. With `scale: false`, only `translate` animates.

- Targets are the elements that move, taken when `flip` is called:
  `flip(list.children, () => list.prepend(item))`. Passing a container
  animates the container.
- Elements added by `change` are not targets. Targets that `change`
  removes are skipped.
- A target with a running `flip` is measured where it currently is (the
  rect includes the running transform), its old animation is cancelled,
  and the new one starts from there.
- A target with a zero-size first or last rect only translates.

## 7. `exit`

```ts
exit(target: Element, options?: ExitOptions): Promise<void>
```

| Option | Default |
|---|---|
| `keyframes` | `[{ opacity: 1, transform: 'none' }, { opacity: 0, transform: 'translateY(0.25rem)' }]` |
| `duration` | `'fast'` |
| `easing` | `'exit'` |
| `remove` | `true` |

- The target becomes `inert` when the exit starts and animates with
  `fill: 'forwards'`, so it holds its last frame until removal.
- When the animation finishes, the target is removed. With
  `remove: false`, the animation stays applied and `inert` stays set; the
  caller hides or removes the element.
- A second `exit` on a target that is exiting returns the same promise.
- `exit` does not move focus. As with `remove()`, a caller whose focus is
  inside the target moves it first. The docs say so.
- The target keeps its space until it is removed. `flip` closes the gap:
  `await flip(siblings, () => exit(option))`.
- An `mb-option` can exit: `mb-listbox` updates on `slotchange` after the
  removal, as for a synchronous `remove()`.

## 8. Testing

| Level | What |
|---|---|
| Setup | Browser tests in `test/browser/motion/`, on the existing web-test-runner configuration. The shared stylesheet that zeroes durations is removed in these tests, as in the `0.3.0` motion tests. Tests step animations with `pause()` and `currentTime` and read `getKeyframes()` and `getTiming()`; none waits on the clock for an animation to finish. |
| Unit | Duration parsing and the rect-delta math, with vitest. |
| Timing | Token names resolve from the target's computed style; a subtree override wins; numbers pass through; built-in defaults without `tokens.css`; unsupported easing falls back to `ease-out`. |
| Reduced motion | `emulateMedia({ reducedMotion: 'reduce' })` and a spy on `Element.prototype.animate`: no helper calls it, each applies its end state, promises resolve. The same for a `0ms` token. |
| `reveal` | First keyframe held with no inline style; plays on entry; targets entering together are offset by `interval`; targets above the viewport shown without animating; `focusin` reveals; `stop()` and abort show every waiting target. |
| `stagger` | Delay per index; resolves after the last animation. |
| `flip` | Keyframes match the measured deltas; `scale: false` translates only; added and removed elements skipped; an interrupted flip starts from the current position; async `change` awaited; a throwing `change` rejects. |
| `exit` | `inert` during the exit; removed after; `remove: false` keeps it; the same promise twice; abort removes at once; exiting the active `mb-option` leaves the listbox as a synchronous `remove()` does. |
| Shadow DOM | Each helper on elements inside a shadow root. |

## 10. Decisions log

| Decision | Alternatives rejected | Reason |
|---|---|---|
| Framework-free functions | Functions plus Lit directives; declarative elements | Works in any framework, tree-shakes, fits a small budget; wrappers can come later |
| All four helpers in one release | Fewer in `0.4.0`, the rest in `0.4.x` | Requested; they share the timing and cancellation rules |
| Timing from the target's computed tokens | Fixed defaults; a global config object | Themes and reduced motion already set the tokens; one source of truth with the components |
| Paused animation with `fill: 'backwards'` for hidden-before-reveal | Inline `opacity: 0`; a CSS class | Nothing written to the element; `cancel()` restores it; no stylesheet needed |
| `IntersectionObserver` for `reveal` | CSS scroll-driven animations | Supported in all three engines; reveal-on-entry is not scroll-linked progress |
| Promises for sequencing | A timeline object | `async`/`await` already expresses it, at no size cost |
| FLIP with `element.animate()` | `document.startViewTransition()` | View transitions block input, need document-unique names, do not reach into shadow roots in all engines, and animate snapshots |
| `exit` makes the target `inert` | `aria-hidden` only; nothing | Blocks clicks and focus as well as the accessibility tree during the exit |
| Abort resolves, never rejects | Reject with `AbortError` | Callers `await exit(el)` without a `try`; the end state is always applied |
