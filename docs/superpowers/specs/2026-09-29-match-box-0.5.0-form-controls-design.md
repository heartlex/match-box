# match-box 0.5.0: form controls

Date: 2026-09-29
Status: approved for planning
Builds on: `docs/superpowers/specs/2026-09-27-match-box-v2-step1-design.md`,
`docs/superpowers/specs/2026-09-28-match-box-v2-step1-followups-design.md`

## 1. Purpose and scope

Step 2 of the component roadmap: form controls, and one shared pattern for
their label, description, and error.

| Piece | What it is |
|---|---|
| `mb-field` | Renders a label, description, and error around any control and connects them to it |
| `mb-input` | A native `<input>` in shadow DOM: types text, email, password, search, tel, url, number; `prefix` and `suffix` slots |
| `mb-checkbox` | A native checkbox input in shadow DOM, with an indeterminate state; its default slot is its label |
| `mb-checkbox-group` | `mb-checkbox`es that submit and validate together, with an optional "select all" parent |
| `mb-switch` | A native checkbox input with `role="switch"`, drawn as a track and thumb |
| `attachField` (core) | The label, description, and error wiring for plain HTML |
| `CheckboxGroupState`, `attachCheckboxGroup` (core) | Parent tri-state and "at least one" validation, headless |
| `fieldConformance`, `checkboxGroupConformance` (`core/testing`) | Suites run against the plain-HTML demos and the components |

`mb-listbox` gains the field protocol (section 3). It ships as `0.5.0`.

Success means:

- every new control submits, resets, restores, and validates like its
  native counterpart, on Chromium, Firefox, and WebKit;
- inside `mb-field`, every control (the three new ones, the group, and
  `mb-listbox`) gets its accessible name and description from the field,
  and shows the field's error at the right time;
- the controls keep the skin's isolation: page CSS does not change them;
  tokens, parts, and slots do;
- the new core pieces pass their conformance suites with plain HTML.

### Non-goals

- Multi-line text (`textarea`), a clear button, a built-in password
  toggle.
- A label position option for checkbox and switch.
- Core state for single inputs, checkboxes, or switches: native inputs
  already provide the behavior.
- Hard isolation from inherited properties (`:host { all: initial }`).
- Select and combobox (steps 3 and 4).

## 2. Shared decisions

- All controls wrap native inputs in shadow DOM, for keyboard, IME,
  mobile keyboards, autofill, and forced colors.
- Form behavior comes from `FormAssociated` (`src/lit/form-associated.ts`):
  value, `required`, `validators`, reset, restore, `:state(invalid)`,
  `:state(user-invalid)`. Focus comes from `DelegatesFocus`.
- Every element has `size` (`sm`, `md`, `lg`) and, except `mb-field`,
  `color` (the five roles), not reflected, as the existing components.
- Component tokens fall back to the size scale, color roles, and motion
  tokens, as in `docs/styling-contract.md`. No new semantic tokens.
- Checkbox and switch share an internal base class in
  `src/components/shared/` for checked state, form value, reset,
  `change`, and the field protocol.

## 3. The field protocol

`FieldControl`, in `src/components/shared/field-control.ts`, is
implemented by `mb-input`, `mb-checkbox`, `mb-switch`,
`mb-checkbox-group`, and `mb-listbox`:

| Member | Set by | Meaning |
|---|---|---|
| `fieldLabel: string` | `mb-field` | Label text; `''` when there is no field |
| `fieldDescription: string` | `mb-field` | Description text |
| `fieldError: string` | `mb-field` | The error shown, or `''` |

- `mb-field` sets them on its slotted control, from the attributes or from
  the text content of the `label`, `description`, and `error` slots.
- The control renders visually hidden elements holding that text inside
  its own shadow root and points its focusable element (or its inner
  `role="group"` / `role="listbox"`) at them with `aria-labelledby` and
  `aria-describedby`. It sets `aria-invalid="true"` while `fieldError` is
  not empty. All references stay inside one shadow root, so they work in
  every engine.
- `mb-field` listens to the control's `input`, `change`, `focusout`, and
  `invalid` events and to the form's `reset`, and reads
  `validationMessage` and `:state(user-invalid)`.
- The error shown is:
  1. the `error` attribute or slot when present, always;
  2. otherwise the control's `validationMessage`, while the control
     matches `:state(user-invalid)` (the user changed it and left it, or a
     form submission reported it);
  3. otherwise nothing. A form reset clears user-invalid, so the error.
- Clicking the field's label focuses the control.
- Without `mb-field`, the control's `field*` members are `''`:
  - `mb-input` is named by a `<label for>` (via `internals.labels`, as
    `mb-listbox` does) or by `aria-label` on the host, forwarded to the
    input;
  - `mb-checkbox` and `mb-switch` are named by their default slot;
  - `mb-checkbox-group` by `aria-label` on the host;
  - `mb-listbox` by its `label` attribute, as today.
- Inside `mb-field`, `mb-listbox` does not render its own `label`; the
  field's label names it.

## 4. `mb-field`

| Surface | Value |
|---|---|
| Attributes | `label`, `description`, `error`, `size` |
| Slots | `label`, `description`, `error` (rich content; win over the attribute), default (one control) |
| Parts | `label`, `required`, `description`, `error`, `control` |
| Tokens | `--mb-field-gap`, `--mb-field-label-color`, `--mb-field-label-font-size`, `--mb-field-description-color`, `--mb-field-error-color` (default: the `danger` role's text color) |

- A `*` follows the label when the control is `required`; it is
  `aria-hidden` because the control exposes required itself.
- The error element is a polite live region and takes no space when
  empty.
- `size` is passed to a control without a `size` attribute, as
  `mb-accordion` does for disclosures, including controls added later.

## 5. `mb-input`

| Surface | Value |
|---|---|
| Attributes | `type` (`text` default; `email`, `password`, `search`, `tel`, `url`, `number`), `value`, `name`, `placeholder`, `required`, `disabled`, `readonly`, `minlength`, `maxlength`, `pattern`, `min`, `max`, `step`, `autocomplete`, `inputmode`, `size`, `color` |
| Methods | `focus()` (DelegatesFocus), `select()` |
| Events | `input` (native, composed); `change` (re-dispatched by the host) |
| Slots | `prefix`, `suffix` (inside the box) |
| Parts | `base` (the box), `input`, `prefix`, `suffix` |
| States | `:state(invalid)`, `:state(user-invalid)` |
| Tokens | `--mb-input-bg`, `-border-color`, `-border-color-hover`, `-border-color-invalid`, `-radius`, `-height`, `-padding-inline`, `-font-size`, `-placeholder-color`, `-duration` |

- Validity: the inner input's `validity` flags and `validationMessage` are
  copied into the host's `ElementInternals` with the input as anchor, so
  messages and the submit popup match a native input. `validators` run
  after the native checks; the first failure wins.
- The value submitted is the inner input's value; `value` reads and writes
  it. The `value` attribute is the reset value.
- The skin draws the `danger` border for `:state(user-invalid)` only.

## 6. `mb-checkbox` and `mb-switch`

| Surface | `mb-checkbox` | `mb-switch` |
|---|---|---|
| Attributes | `checked`, `indeterminate`, `value` (default `on`), `name`, `required`, `disabled`, `size`, `color` | the same, without `indeterminate` |
| Role | native checkbox (`aria-checked="mixed"` when indeterminate) | `role="switch"` on the native input |
| Default slot | the label | the label |
| Parts | `base`, `box`, `mark`, `label` | `base`, `track`, `thumb`, `label` |
| Tokens | `--mb-checkbox-size`, `-bg`, `-border-color`, `-bg-checked`, `-mark-color`, `-radius`, `-gap`, `-duration` | `--mb-switch-track-width`, `-track-height`, `-thumb-size`, `-track-bg`, `-track-bg-checked`, `-thumb-bg`, `-duration` |

- The `checked` attribute is the initial and reset state; the `checked`
  property is the current state, as on a native checkbox.
- Form value: `name=value` when checked, nothing otherwise. `required`
  fails with `valueMissing` when unchecked.
- Space and clicking the label toggle. The host re-dispatches `change`;
  `input` is native.
- `indeterminate` shows the dash and clears when the user toggles.
- The switch's thumb moves with `--mb-motion-easing-spring`; durations are
  `0ms` under reduced motion.
- The accessible name comes from the slotted label. If an engine does not
  name the input from slotted text, the control names it from a hidden
  text copy, as in the field protocol; tests check the name in all three
  engines.

## 7. `mb-checkbox-group`

| Surface | Value |
|---|---|
| Attributes | `name`, `required`, `disabled`, `select-all`, `select-all-label` (default `Select all`), `size`, `color` |
| Properties | `values: string[]` |
| Children | `mb-checkbox` elements (light DOM) |
| Parts | `group`, `select-all` |
| Tokens | `--mb-checkbox-group-gap` |

- The group is the form-associated element (as `<select multiple>` and
  `mb-listbox`): one form entry per checked child `value`. A child's own
  `name` is ignored inside a group.
- `required`: at least one checked, else `valueMissing` with the message
  `Select at least one option.`, anchored to the first checkbox.
- `select-all` renders a parent checkbox before the children, labelled by
  `select-all-label`. It is checked, unchecked, or indeterminate from the
  enabled children; activating it checks every enabled child, or unchecks
  them all when all are checked. Disabled children never change.
- An inner `role="group"` is named by the field protocol or the host's
  `aria-label`. Keyboard: Tab between checkboxes, Space toggles (APG
  checkbox pattern).
- `disabled` disables every child.
- Children are stacked vertically; `::part(group)` can lay them out in a
  row.

## 8. Headless core

### `CheckboxGroupState` (`src/core/state/checkbox-group.ts`)

- Items: `{ key: string; checked: boolean; disabled: boolean }[]`, set
  with `setItems(items)`.
- `parentState: 'checked' | 'unchecked' | 'mixed'`, from enabled items
  (`unchecked` when there are none).
- `setChecked(key, on)`, `toggleAll()` (checks every enabled item unless
  all are checked, then unchecks them), `checkedKeys`.
- `required` option; `valueMissing` is true when required and nothing is
  checked.
- A `Store`, as the other state classes.

### `attachCheckboxGroup` (`src/core/dom/checkbox-group.ts`)

`attachCheckboxGroup({ root, parent, items }, { required })`, with native
checkboxes: `parent` optional, `items: () => HTMLInputElement[]`. It keeps
the parent's `checked` and `indeterminate` in sync, handles parent
activation, and sets `setCustomValidity('Select at least one option.')` on
the first item while `valueMissing`. Returns a behavior with `state` and
`dispose()`, like `attachListbox`.

### `attachField` (`src/core/dom/field.ts`)

`attachField({ control, label, description, error })`, with a native
control and plain elements: gives them ids, sets `for` on a `<label>`
(or `aria-labelledby` otherwise), `aria-describedby` (description, then
error), and `aria-invalid`; shows `control.validationMessage` in `error`
after the user changes the control and it loses focus, or on its
`invalid` event, and clears it on the form's `reset` and when the control
becomes valid. A custom message set with `field.setError(text)` wins until
cleared with `setError('')`. Returns `{ setError, dispose }`.

### Conformance suites (`src/core/testing/`)

- `fieldConformance`: name and description from the field; error hidden
  until the user changes and leaves the control; shown on a submit
  attempt; cleared on reset and when valid; `aria-invalid` while shown; a
  custom error wins; axe.
- `checkboxGroupConformance`: parent state for none, some, and all
  checked; parent activation checks and unchecks enabled items only;
  disabled items unchanged; required validity; Space on the parent; axe.

Both run in `test/browser/demos.test.ts` against new plain-HTML demos in
`site/demos/demos.js`, and against the components.

## 9. Testing

| Level | What |
|---|---|
| Conformance | `fieldConformance`, `checkboxGroupConformance` for demos and components; the existing suites unchanged |
| `mb-input` | FormData, reset, restore; validity flags and messages match a native input for each type; custom validators after native; `change` re-dispatched; `<label for>` and host `aria-label` forwarded; slots render |
| `mb-checkbox`, `mb-switch` | Space and label click toggle; `name=value` only when on; `valueMissing`; reset to the `checked` attribute; indeterminate is `mixed` and clears; the switch has `role="switch"`; the name comes from the slotted label in all engines |
| `mb-checkbox-group` | `values` round-trip; one entry per checked child; required and its message; select-all in all three states; disabled children skipped; child `name` ignored |
| `mb-field` | Name and description reach each control type, `mb-listbox` included; error timing (attribute at once, message after change-and-leave or submit); reset clears; label click focuses; live region; `*` for required; `size` passed down |
| Cross-component | axe per size in both themes; forced colors; reduced motion; `sm` target size ≥ 24 × 24 px; styling contract (tokens, parts, no host margin); page CSS such as `* { … !important }` does not change the controls |

## 12. Decisions log

| Decision | Alternatives rejected | Reason |
|---|---|---|
| A separate `mb-field` wrapper | Label, description, and error attributes on each control | One implementation of the pattern for every control, present and future |
| `mb-field` renders everything in its shadow root; controls hold hidden text copies | Light-DOM `<label for>` inserted by the field; the unshipped `referenceTarget` | Keeps the skin isolated from page CSS; element references cannot cross into a sibling shadow root |
| `mb-input` for the text control | `mb-text-field` next to `mb-field` | "Field" means the labelled unit; the control mirrors `<input>` |
| Native inputs inside every control | ARIA `role="checkbox"` on a `div` | Keyboard, IME, autofill, forced colors, and validity come from the platform |
| `mb-switch` as its own element | A checkbox variant | Requested; `role="switch"` and on/off semantics differ from a checkbox |
| The group is the form control | Each checkbox submits itself | "At least one" validity needs one owner; matches `mb-listbox` and `<select multiple>` |
| Core only where there is logic | Full parity; none | Native inputs already cover single controls; the field wiring and the group logic are real behavior |
| Error after change-and-leave or submit | Error as soon as invalid | An untouched required field is not an error yet |
