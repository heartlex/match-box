# match-box 0.6.0: matchbox default skin

Date: 2026-09-29
Status: draft, awaiting review
Builds on: `docs/superpowers/specs/2026-09-29-match-box-0.5.0-form-controls-design.md`
Source: the matchbox design-system sheets supplied by the user
(typography, grid, spacing, components, inputs, navigation, table, upload).

## 1. Purpose and scope

Replace the library's default skin with the matchbox look. The token layer and
every existing component change; the public API (elements, attributes,
parts, `--mb-*` variables) stays.

| In scope | Out of scope (later releases) |
|---|---|
| Token values: palette, spacing, type, radius, sizes, dark theme | New components: split button, radio, chips, search bar, message, pagination, slider, tab bar, header, sidebar, table, upload |
| A few new semantic tokens (§3.3) | The button "processing" (spinner) state |
| A free stand-in font, shipped as `match-box/fonts.css` | The 12-column grid (app layout guidance, not a component concern) |
| Restyling mb-button, mb-input, mb-field, mb-checkbox, mb-switch, mb-checkbox-group, mb-listbox, mb-option | A second, opt-in skin: matchbox **replaces** the default |
| Adapting mb-disclosure, mb-accordion, mb-dialog | |

Non-goals: pixel copies of the sheets where they conflict with WCAG AA
(§3.4, §3.5); an icon set (only one built-in icon, §4.3).

## 2. Decisions from brainstorming

| Question | Decision |
|---|---|
| Replace or add a skin | Replace the default skin |
| Aeonik (commercial) | Stack `'Aeonik', 'Geist', system-ui, …`; ship Geist (OFL) as the stand-in |
| Stand-in font | Geist, variable, latin subset |
| Color roles | Keep the five roles (`neutral`, `primary`, `secondary`, `tertiary`, `danger`); remap values |
| Sizes sm / md / lg | 32 / 40 / 48 px |
| Dark theme | Keep; derive from the matchbox navy |
| Approach | Tokens first, then component CSS only where matchbox differs in structure |

## 3. Tokens (`src/tokens/tokens.css`)

The file keeps its four sections (primitives, light semantic, dark semantic
twice, reduced motion) and its rule that only the semantic tier references
primitives.

### 3.1 Primitives (private)

Values read from the sheets (there is no color page; see §9).

| Scale | Steps |
|---|---|
| `--mb-indigo-*` | 50 `#EEEEFF`, 100 `#DCDCFF`, 300 `#9D9DFF`, 400 `#7B7BFF`, 450 `#6666FF`, 500 `#5757FF`, 700 `#2E2EC7` |
| `--mb-navy-*` | 950 `#0E0E30`, plus 900 / 800 / 700 lighter steps for dark surfaces, chosen during implementation to meet §3.4 |
| `--mb-gray-*` | Cool grays 0–900, re-tinted toward navy (canvas `#F5F5F8`, borders about `#D7D7DE`, disabled fill about `#E6E6EA`, disabled text about `#9A9AA6`) |
| `--mb-red-*` | 50 `#FDECEC`, 500 `#F04444`, plus darker/lighter steps for text and dark mode |
| `--mb-green-*`, `--mb-amber-*` | 50 tint, a solid step, and a text step that meets 4.5:1 |

The blue, violet and teal primitives are removed.

### 3.2 Roles (same five, same six tokens each)

| Role | solid | solid-hover | on-solid | text | subtle | border |
|---|---|---|---|---|---|---|
| primary | indigo 500 | indigo 450 | white | indigo 500 | indigo 50 | indigo 500 |
| secondary | navy 950 | navy 800 | white | navy 950 | gray 100 | navy 950 |
| tertiary | indigo 50 | indigo 100 | indigo 700 | indigo 500 | indigo 50 | indigo 300 |
| danger | red (text step) | darker red | white | red text step | red 50 | red 500 |
| neutral | gray 100 | gray 200 | navy 950 | navy 950 | gray 100 | gray 300 |

`--mb-color-fg-default` becomes navy 950. `--mb-color-border-focus` becomes
indigo 500.

### 3.3 New semantic tokens

| Token | Purpose |
|---|---|
| `--mb-color-<role>-solid-active` (5) | matchbox pressed state: darker than solid (primary: indigo 700) |
| `--mb-color-<role>-subtle-active` (5) | Pressed state for outline/ghost buttons (primary: indigo 100) |
| `--mb-color-fg-warning`, `--mb-color-fg-danger` | Status text next to the existing `--mb-color-fg-success` |
| `--mb-color-bg-success`, `--mb-color-bg-warning`, `--mb-color-bg-danger` | Status banner backgrounds (the field error message) |
| `--mb-font-size-caption` (11px), `--mb-font-size-label` (12px), `--mb-font-size-subtitle` (24px), `--mb-font-size-h4` (32), `--mb-font-size-h3` (48), `--mb-font-size-h2` (64), `--mb-font-size-h1` (72) | The matchbox type scale (h1–h3 with -2% letter spacing, line height 120/120/140%) |
| `--mb-font-weight-light` (300), `--mb-font-weight-regular` (400), `--mb-font-weight-medium` (500) | Next to `--mb-font-weight-strong`, which becomes 700 |
| `--mb-border-width-control` (1.5px) | matchbox outline stroke |

Existing semantic tokens keep their names; only their values change.

### 3.4 Spacing, shape, type, sizes

- **Spacing:** the 4-pt scale `--mb-space-1` (4) `-2` (8) `-3` (12) `-4` (16)
  `-6` (24) `-8` (32) `-10` (40). The inline and stack aliases keep their
  names.
- **Radius:** `--mb-radius-control` 8px, `--mb-radius-surface` 16px; a
  private 4px step for the checkbox.
- **Type:** body 14px, small 12px, line height 1.5, weight strong 700.
  Deviation from the sheets: matchbox body is 12px; inside controls md uses 14px
  and sm uses 12px so control text stays readable.
- **Sizes:**

| Size | Height | Inline padding (button / input) | Font | Icon |
|---|---|---|---|---|
| sm | 32px | 12px / 12px | 12px | 16px |
| md | 40px | 24px / 16px | 14px | 20px |
| lg | 48px | 30px / 16px | 16px | 24px |

Buttons with a prefix icon use a 4px icon gap at every size (the sheet's
"24 · 4 · 24").

### 3.5 Contrast rule

Every text/background token pair a component uses must meet 4.5:1, and
every border or UI mark (checkbox box, switch track, focus ring) 3:1, in
both themes. Where the sheet breaks this, the token moves the least amount
that passes and keeps the sheet's direction:

- **Primary hover:** the sheet lightens to about `#7B7BFF` (white text
  about 3.4:1). It uses indigo 450 `#6666FF` instead.
- **Danger text and solid:** the step that passes, not the sheet's
  `#F04444`, which stays the border and icon color.

### 3.6 Dark theme

Canvas navy 950, surfaces the navy 900/800 steps, borders navy 700.
Indigo solid becomes 400 with a navy on-solid; text steps lighten (indigo
300, red and green text steps). Both dark blocks (explicit
`[data-theme='dark']` and the `prefers-color-scheme` copy) stay identical.

## 4. Components

Every component keeps its `--mb-<component>-*` variables. Forced colors,
reduced motion, and the pinned line-height/letter-spacing protection stay as
they are.

### 4.1 mb-button

- Variants: default = Contained, outline = Outlined, ghost = Texted.
- Hover uses solid-hover; pressed (`:active`) uses solid-active.
  `--mb-button-press-scale` stays but defaults to `1` (no scaling).
- Outline: 1.5px border (`--mb-border-width-control`) in the role border
  color. Outline and ghost hover use subtle; pressed uses subtle-active,
  and outline keeps its border.
- Disabled: gray fill and gray text for default. Outline keeps a gray
  border on transparent. Ghost has gray text only.
- Icon only (no text in the default slot, prefix or suffix present): square,
  inline size equal to the height. It's detected with the existing slot
  observation; no new attribute.
- Weight medium (500), per the sheet's button text.

### 4.2 mb-input

- 1.5px border in gray 300, radius 8px, surface background.
- Hover: border indigo 500. Focus-within: border indigo 500 plus the
  existing focus ring when focus is visible.
- Placeholder: `--mb-color-fg-subtle`. Disabled: gray fill, gray text,
  gray border.
- `:state(user-invalid)`: border red 500. No built-in icon; a suffix slot
  can hold one.

### 4.3 mb-field

- Label: 12px (`--mb-font-size-label`), weight medium, fg-default, 4px
  above the control. The required marker `*` is red 500, weight medium,
  with no space before it.
- Description: 12px, fg-muted, 4px below the control.
- Error: the matchbox "message" banner. The row takes no space when empty
  (unchanged). When shown: background `--mb-color-bg-danger`, radius 8px,
  padding 4px 8px, 12px text in `--mb-color-fg-danger`, and a built-in
  12px round "!" icon (inline SVG, `aria-hidden`, part `error-icon`)
  before the text. When both are present, the banner replaces the
  description, as it does today.

### 4.4 mb-checkbox

- Box: 18px, radius 4px, 1.5px border gray 400 on surface. Hover: border
  indigo 500.
- Checked and indeterminate: indigo 500 fill, white mark.
- Disabled: border gray 300. Checked or indeterminate disabled: indigo 100
  fill, white mark.
- The `sm` / `lg` sizes scale the box to 16 / 20px. The label uses the size
  font.

### 4.5 mb-switch

- Track: pill, 36×20px at md (sm 32×18, lg 44×24). Off: surface fill,
  1.5px gray 300 border, gray 400 thumb. On: indigo 500 fill, white thumb.
- Disabled off: gray 100 fill, gray 200 border, gray 200 thumb. Disabled
  on: indigo 100 fill, white thumb.
- The geometry variables stay on `[part=base]` (0.5.0 fix).

### 4.6 mb-checkbox-group

12px gap between items; the select-all checkbox and its separator follow the
checkbox look; the legend uses the field label style.

### 4.7 mb-listbox and mb-option

- Listbox: surface, radius 8px, 1px border-default, `--mb-shadow-overlay`
  (soft, e.g. `0 4px 16px rgb(14 14 48 / 0.08)` in light mode), padding 4px.
- Option: min height 40px, padding 0 12px, radius 8px, 14px text. Hover
  or active-descendant: neutral subtle. Selected: primary subtle, fg-default
  text. In multiple mode, the check indicator uses the §4.4 checkbox look.
- Focus-visible on the listbox keeps the ring.

### 4.8 Adapted: mb-disclosure, mb-accordion

- Trigger: min height 48px, padding 0 16px, 14px, weight medium,
  fg-default; the chevron sits at the inline end, rotates when expanded,
  and is 20px.
- Hover: neutral subtle. Panel: padding 8px 16px 16px, fg-muted.
- Accordion items are separated by a 1px border-default divider; the
  container has radius-surface and a 1px border.

### 4.9 Adapted: mb-dialog

- Surface: radius 16px, padding 24px, `--mb-shadow-overlay`.
- Title: 24px (subtitle), weight bold, fg-default, line height 1.2.
  Body: 14px, fg-muted.
- Backdrop: navy 950 at 40%.

## 5. Font (`match-box/fonts.css`)

- Vendor `src/tokens/fonts/Geist-Variable.woff2` (latin subset) and
  `src/tokens/fonts/OFL.txt`. The build already copies `src/tokens` to
  `dist/tokens`.
- `src/tokens/fonts.css`: one `@font-face` for `'Geist'`, weights 100–900,
  `font-display: swap`, a `url()` relative to the CSS file.
- `package.json` export: `"./fonts.css": "./dist/tokens/fonts.css"`.
  `sideEffects` already includes `**/*.css`.
- `--mb-font-sans`: `'Aeonik', 'Geist', system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif`.
  An app with an Aeonik license loads Aeonik and gets it; an app that skips
  `fonts.css` falls back to the system font.

## 6. Testing

- **Contrast (new unit test):** parses `tokens.css`, resolves primitives,
  and asserts every pair the components use (a listed table in the test),
  in light and dark: 4.5:1 for text, 3:1 for borders and marks.
- **Browser styling tests:** update the expected values of the existing
  assertions; don't delete them. Add:
  - md button and input heights are 40px;
  - the outline border is 1.5px;
  - a pressed primary button uses solid-active (no transform);
  - the icon-only button is square;
  - the field error banner has the danger background only while an error
    is shown, and takes no space when empty;
  - with `fonts.css` loaded, a control's computed font family starts with
    Aeonik, and `document.fonts` reports Geist loaded.
- Page-CSS, forced-colors, reduced-motion and conformance suites stay green
  without changes to their assertions.
- The Storybook smoke test and the site build stay green.

## 8. Budgets and release

- `match-box/tokens.css`: raised from 1700 to its measured gzip size,
  expected about 2100, recorded here when measured.
- `match-box/fonts.css`: new entry, 300 B. The woff2 file isn't in the gzip
  budgets; the size script asserts it's at most 80 KB.
- `match-box/components` and `define/all.js`: stay at or under 15900. If the
  error icon or the icon-only detection pushes them over, trim first; a raise
  needs a ruling recorded here.
- Version 0.6.0. Visual breaking change; no API removal.

## 9. Risks and open points

- **No color page:** the palette is read from rendered sheets. The user can
  correct any primitive later by value; the role mapping won't move.
- **Aeonik metrics differ from Geist:** line heights are pinned per
  component, so switching fonts doesn't shift layout beyond glyph width.
- **Size headroom:** components had 3 B spare after 0.5.0.
